## GOAL
Move the parent school search INTO the parent dashboard, taking over the URL `/parent/search`
(retire the public parent search page; guests use the generic `/search`). The dashboard search must
expose logged-in-only enrichments: save-to-shortlist, compare bar → `/parent/compare`, per-result
**Apply** button, a **"You applied" status badge**, and an **active-child context** banner.

Mirror the proven agent in-dashboard search (`DashboardSearchContent` → `/agent/(protected)/dashboard/search`).
DO NOT touch agent/public/school search behavior. Changes to shared files MUST be additive & opt-in
(new optional props defaulting to current behavior).

## KEY FACTS (verified)
- `Portal` type: `@/lib/portal-url`. activePortal for this feature = `'parent'`.
- `SchoolHit` (from `@/modules/school-search`): has `documentId`, `id`, `slug`, `name`, `suburb`, `state`,
  `logoUrl`, `lowestAnnualTuition`, `curriculumOffered`. Result cards link to `/parent/schools/{slug}`.
- Bookmark/shortlist: reuse `useBookmarkToggle(school)` from `@/modules/school-search/hooks/useBookmarkToggle`
  (returns `{ isBookmarked, isPending, toggle }`). Works server-side when authed.
- Compare store (`@/modules/school-search/stores/use-school-search-store`): `compareList: string[]`,
  `toggleCompare(schoolId, max)`, `isInCompare(schoolId)`. Compare id = **`school.documentId`** (mirrors
  `cards/CardActions`). Max for authed parent = `COMPARE_MAX_ADVANCED` (from filter-options.constants).
- Applications: `useParentApplications` + type `ParentApplication` + `ApplicationStatusBadge` exported from
  `@/modules/applications`. `ParentApplication.school.documentId` matches `SchoolHit.documentId`;
  `ParentApplication.status: ApplicationStatus`; `ParentApplication.documentId` is the application id.
- Active child: `@/modules/students` exports `useActiveChildStore` (`{ activeChildId, setActiveChild }`),
  `useParentStudents()`, `ParentStudentAvatar`. (Students list at `data.data` w/ `documentId, firstName, lastName, photo?.url`.)
- Header already renders `ParentChildSwitcher` globally for parents → DO NOT add a second switcher;
  the context banner is READ-ONLY (reflects the same store).
- `resolvePageTitleEntry` auto-derives parent titles from `PORTAL_NAV.parent` → adding the nav item is
  sufficient for the header title. No edit to `resolve-page-title.ts`.
- `cn()` uses tailwind-merge → later position classes override earlier (`absolute` overrides `fixed`).
